Architecture

One global, R1UI, holding a factory per component. A factory takes a host element and a props object, renders into the host and returns a handle. There is no framework, no build step and no dependency: the app, the artifact copy and the GitHub Pages copy load the same two files.

Contract

  • R1UI.name(host, props) renders and returns { el, update(partial), destroy() }.
  • Props go in, callbacks (onChange, onToggle, onReselect) come out. A component never reads the app's state.
  • update() never fires a callback. It syncs the DOM in place (focus and scroll kept) when the item ids are unchanged, and rebuilds only when they change.
  • destroy() removes listeners and empties the host.

Accessibility

  • WAI-ARIA Authoring Practices patterns: tablist with roving tabindex, radiogroup, listbox, toolbar, spinbutton, disclosure, live regions.
  • Arrow keys, Home and End move within a group; Enter and Space select; disabled items are skipped by focus except in a listbox, where a disabled option stays readable with its reason.
  • State is in attributes (aria-selected, aria-checked, aria-expanded, aria-pressed, aria-busy, aria-invalid), with the CSS keyed to them.
  • Status marks carry text alternatives; busy states announce themselves; errors are assertive.

States and edge cases

  • Loading (skeletons or a spinner with text), empty (a sentence), disabled, error (tone + aria-invalid).
  • Zero items, one item, a value not among the items (nothing selected, a console.warn), a disabled current value, long labels (ellipsis + title), rapid repeated updates.

Responsive and theming

  • Tab strips scroll sideways; toolbars and option cards wrap; nothing is wider than its container.
  • 44 px targets on coarse pointers; motion off under prefers-reduced-motion.
  • All colours come from the tokens in ui.css, which redefines them for dark mode (OS setting or data-theme).

Usage

<link rel="stylesheet" href="ui.css">
<script src="ui.js"></script>

var tabs = R1UI.tabs(document.getElementById("viewTabs"), {
  ariaLabel: "Views",
  items: [{ id: "map", label: "Map", panel: "paneMap" }, { id: "plans", label: "Floor plans", panel: "panePlans", disabled: true }],
  value: "map",
  onChange: function (id) { showView(id); }
});
tabs.update({ items: [...], value: "plans" });   // later: enable, select, relabel; focus is kept
tabs.destroy();

R1UI.tabs view tabs

A tablist whose buttons show and hide their panels. Manual activation by default: arrows move focus, Enter or Space selects, so a heavy panel is not built while the user passes over its tab. The strip scrolls sideways when it is too narrow.

R1UI.segmented segmented control

A radio group drawn as one bar: the massing source, the form. Arrow keys move and select. Choosing the chosen item again fires onReselect, which the app uses to redraw a form while keeping its unit settings.

proptypenotes

valueid | null
onChange / onReselect(id) => void
disabled, busybooleanbusy also sets aria-busy

  items: [{ id: "single", label: "Single building" }, { id: "courtyard", label: "Courtyard" }],
  value: null, disabled: true,
  onChange: function (k) { applyForm(k, false); },
  onReselect: function (k) { applyForm(k, true); } });
